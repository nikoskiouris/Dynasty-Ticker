Privacy

What this ticker stores, and what it never sees.

Last updated November 7, 2026. Dynasty Ticker is a static website at dynastyticker.com. It talks to Sleeper from your browser. There is no Dynasty Ticker account.

Who we are

Dynasty Ticker is the open-source project at github.com/nikoskiouris/Dynasty-Ticker. Contact is GitHub issues on that repo, not a mailbox or street address.

What the app fetches

When you search a username or load a league, your browser calls the public Sleeper API for league, roster, matchup, draft, transaction, and player data. Rankings and a Sleeper trade-market file are bundled as static files in this repo. We do not proxy that traffic.

What stays on your device

The ticker uses browser localStorage, not cookies:

  • Whether the left board is open or closed
  • A short-lived cache of Sleeper NFL player metadata (in IndexedDB when it is too big for localStorage)
  • The last Sleeper league you opened here (league id and name, your team id and manager name), so the home page can offer to open it again. “Forget this league” on the home page removes it. The sample league is never saved.

The trade you are building (player and pick ids, names, and the team you picked to browse) sits in session storage for this tab only, so a reload or connecting Sleeper does not erase it. So does the trade you last cleared or replaced, so Restore draft still works after a reload. It is gone when you close the tab. It is never sent anywhere.

Clear site data in your browser to wipe the local copy.

Cookies and ads

This app does not set cookies, does not show ads, and does not install Google Analytics or any other third-party tracker.

Page counts

The live site sends a small cookieless note to its own host for each page you open and for a few actions: a trade checked, a share link copied or opened, a league connected, and a trade typed into the describe box (only what kind of message it was, never the words). Pages are sent as patterns such as /l/:id or /player/:id. League ids, player ids, share codes, usernames, and query strings are not sent. The first note of a visit also says where you came from, reduced to the website’s host name (for example reddit.com), and a utm_source tag if the link had one.

The host adds these to per-day totals. To count unique visitors for a day, it may keep a shortened hash of a secret, the date, your IP address, and your browser. The date is part of the hash, so you are a different hash the next day. The raw address is not stored. The totals are not shown on the site. Do Not Track or Global Privacy Control in your browser turns these notes off. The host and the Sleeper API may still log ordinary request metadata on their side.

Searched usernames

When you search a Sleeper username and one of that user's leagues actually opens, the live site adds that username to a list on the site host. Next to it the host keeps the public Sleeper user id, when it was first and last opened, and how many times. A later open updates that same row. Every other username already on the list stays. A typo never opens a league, so it is not saved. The saved name is the one Sleeper returns, so a misspelling stays the same person instead of a new one. The league id is not saved. The list is not shown anywhere on the site.

Share links

A shared trade link (/t/…) holds the trade itself: Sleeper player and pick ids, the scoring format, and the date the prices were taken. Trade and league addresses (/trade?give=…&get=…, /l/<league id>/team?me=<team>) name public Sleeper ids the same way. Anyone with a link sees the same public view. There are no secrets to put in a URL.

Children

This is a fantasy-football tool. It is not directed at children under 13, and it does not ask for personal profiles beyond a public Sleeper username you type yourself.

Contact
